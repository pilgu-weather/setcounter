# Set Counter 출시 준비 감사 보고서

검사 완료일: 2026-08-09

## 결론

앱 코드와 Android 패키지의 로컬 출시 기반은 준비됐다. 그러나 최종 HTTPS 호스트 연결, 공개 정책 URL 검증, Play App Signing용 Digital Asset Links, 최신 스크린샷, Play Console 설문·테스트는 출시 전에 반드시 완료해야 한다. 현재 상태를 `바로 프로덕션 제출 가능`으로 보지는 않는다.

## 이번 감사에서 보완한 항목

1. 운영 HTTPS 응답에 HSTS를 추가하고 CSP에 `object-src 'none'`, `form-action 'self'`를 추가했다.
2. 공개 개인정보 처리방침에 처리자, 문의처, 정확한 보안 식별값 보관 기간, 외부·국외 처리, 정책 변경 고지를 보완했다.
3. 이용약관에 만 18세 이상 대상과 약관 변경·대한민국 법령 적용을 보완했다.
4. 가입 시 약관·개인정보 동의 버전과 시각이 DB에 저장되는지 재확인했다.
5. Git에 들어 있던 과거 운동 기록 백업 JSON을 추적 대상에서 제거하고 `backups/` 전체를 제외했다.
6. Python 의존성을 보안 수정 버전으로 올리고 하위 보안 버전을 명시적으로 고정했다.
7. Python 3.11 새 환경에서 설치, 취약점 감사, 전체 테스트를 수행했다.
8. Play 데이터 보안·건강 앱·앱 콘텐츠 답변표를 실제 앱 동작 기준으로 다시 작성했다.
9. 2026년 8월 31일부터 신규 앱에 적용되는 API 36 요건을 확인했으며 현재 targetSdk 36이다.
10. 원형 런처 아이콘 바깥을 투명 처리하고 Android lint의 실루엣 경고를 제거했다.
11. 정지 계정이 기존 로그인 세션으로 계속 접근하던 경로를 차단하고 회귀 테스트를 추가했다.

## 출시 차단 항목

1. 최종 서비스 호스트를 확정하고 TWA의 세 위치(`launch_url`, `asset_statements`, Manifest host)를 같은 값으로 설정해야 한다.
2. 최종 호스트에서 `/privacy`, `/terms`, `/account-deletion`이 로그인 없이 열려야 한다.
3. Play App Signing 인증서 SHA-256을 서버 환경에 넣고 `/.well-known/assetlinks.json`과 Google DAL 검증을 완료해야 한다.
4. 운영 환경에서 Secure 쿠키, HSTS, HTTPS, DB 마이그레이션과 데이터 건수를 확인해야 한다.
5. 2026-07-22 스크린샷은 현재 UI와 차이가 있으므로 최신 배포 화면으로 교체해야 한다.
6. Play Console의 데이터 보안, 건강 앱, 콘텐츠 등급, UGC, 계정 삭제 설문을 제출해야 한다.
7. 계정 요건에 해당하면 실기기 인증 및 12명·14일 비공개 테스트를 완료해야 한다.

## 저장소 보안 주의

과거 운동 백업 JSON은 현재 브랜치에서 삭제했지만 이전 Git 커밋에는 남아 있다. 저장소를 외부에 공개했거나 제3자에게 공유했다면 별도의 Git 이력 정리와 접근 토큰·계정 권한 점검이 필요하다. 이력 재작성은 기존 복제본에 영향을 주므로 자동으로 수행하지 않았다.

## 법률 문서 주의

현재 문서는 실제 앱 동작을 기준으로 작성한 운영 초안이다. 최종 배포 서버의 법인명·리전·계약 구조가 바뀌면 국외 처리 내용을 갱신해야 한다. 법률 자문을 대체하지 않으며, 사업자 형태와 대한민국 개인정보 보호 관련 의무에 대한 최종 검토가 필요하다.
